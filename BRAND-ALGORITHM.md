# Brand Identity Pipeline — AI Design Studio

**Полный алгоритм: Бриф → Анализ → Стратегия → Превью → Исполнение → Доставка**

> Методологии: Landor 4D, Ignyte, DeSantis Breindel, Jung Archetypes
> Справочники: references/*.md (читать по мере надобности)
> Шаблоны артефактов: templates/strategy/*.md

**ГЛАВНОЕ ПРАВИЛО:** Каждое дизайн-решение = ссылка на данные брифа.
Не "я выбрал Cormorant потому что красиво", а "клиент указал liked_logos: Chanel/Dior (высокий контраст serif) + luxury=2 (тёплый) → Cormorant Garamond Light 300".

## PIPELINE (Quick Reference)

```
БРИФ (brief-response.json)
  │
  ▼
ФАЗА 0: ВАЛИДАЦИЯ БРИФА
  проверить полноту → запросить / вывести недостающее
  │
  ▼
ФАЗА 1: ГЛУБОКИЙ АНАЛИЗ → brief-analysis.md
  1.1 Психографика аудитории (Read brief → таблица)
  1.2 Конкурентный аудит (WebFetch urls → таблица 7 элементов + white space)
  1.3 Анализ референсов (WebFetch admired_brands → что взять / что нет)
  1.4 Анализ эталонных логотипов (liked_logos → пропорции, вес, spacing)
  1.5 Positioning Map (2 оси, конкуренты, наша позиция)
  │
  ▼ GATE 1: brief-analysis.md заполнен по шаблону, все поля с данными
  │
  ▼
ФАЗА 2: БРЕНД-СТРАТЕГИЯ → brand-strategy.md
  2.1 Архетип (Read references/archetypes.md → матрица → 70/30)
  2.2 Палитра (Read references/color-psychology.md → 5 критериев → 5 цветов)
  2.3 Типографика (Read references/font-matrix.md → архетип → пара)
  2.4 Tone of Voice (архетип + tone → "говорим / не говорим")
  2.5 Стиль декора и изображений
  │
  ▼ GATE 2: brand-strategy.md заполнен, контраст проверен, психо-чеклист пройден
  │
  ▼
ФАЗА 3: ПРЕВЬЮ КЛИЕНТУ
  3.1 Создать palette-preview.html (палитра + шрифты + логотип на одном экране)
  3.2 Скриншот через Playwright
  3.3 Отправить клиенту (WhatsApp / email)
  3.4 Получить фидбэк → скорректировать brand-strategy.md
  │
  ▼ GATE 3: клиент подтвердил направление (или правки внесены)
  │
  ▼
ФАЗА 4: ИСПОЛНЕНИЕ
  4.1 CSS дизайн-система (--color-*, --font-*, --sp-*)
  4.2 Логотип SVG outlined → assets/logos/<client>/
  4.3 Deliverables по пакету (brandbook, cards, letterhead, social)
  4.4 АУДИТ: каждый файл vs brand-strategy.md (таблица сверки)
  4.5 Quality check: Playwright скриншоты + @media print
  │
  ▼ GATE 4: аудит пройден + все deliverables проверены визуально
  │
  ▼
ФАЗА 5: ДОСТАВКА
  5.1 brand.json → output/<client>/
  5.2 deliver-v2.js → ZIP
  5.3 Отправить клиенту
```

## ФАЗА 0: ВАЛИДАЦИЯ БРИФА

**Инструмент:** `Read(output/<client>/brief-response.json)`

### Обязательные поля (без них не начинать):

| Поле | Что делать если пустое |
|------|----------------------|
| company_name | Спросить у Юрия |
| company_description | Спросить у Юрия |
| ideal_client | Спросить у Юрия |
| competitors[] (мин. 1 url) | Найти самому через WebSearch по отрасли + региону |
| scales (modern, luxury, etc.) | Спросить у Юрия |
| tone | Вывести из brand_person + brand_words |

### Желательные (можно вывести):

| Поле | Как вывести |
|------|------------|
| admired_brands | Спросить у Юрия или пропустить шаг 1.3 |
| liked_logos | Спросить у Юрия или пропустить шаг 1.4 |
| brand_words | Вывести из brand_person + company_description |
| brand_emotions | Вывести из tone + ideal_client |
| avoid_colors | По умолчанию: нет ограничений |
| differentiator | Вывести из конкурентного аудита (Фаза 1) |

## ФАЗА 1: ГЛУБОКИЙ АНАЛИЗ

**Артефакт:** `output/<client>/brief-analysis.md`
**Шаблон:** `templates/strategy/brief-analysis-template.md`

### 1.1 Психографика аудитории → визуальные принципы

**Инструмент:** Read(brief-response.json) → анализ ideal_client + brand_emotions

Таблица перевода (ключевые паттерны):

| Психографика | Визуальный принцип |
|-------------|-------------------|
| Ценит традиции и наследие | Serif, приглушённые тона, классические пропорции |
| Стремление к статусу | Тёмные фоны, золото, контрастная типографика |
| Ценит простоту и честность | Светлые фоны, пастельные тона, открытые шрифты |
| Занятые профессионалы | Минималистичные макеты, читаемая типографика |
| Ценит уют и красоту | Тёплые тона, мягкие формы, текстуры |
| Творческий, нонконформист | Яркие акценты, нестандартные сетки |

**Действие:** Выбрать 3-4 принципа. Записать с обоснованием.

### 1.2 Конкурентный визуальный аудит

**Инструмент:** `WebFetch(competitors[].url)` для каждого конкурента

Заполнить таблицу из шаблона (7 элементов × N конкурентов).
Обязательно заполнить колонки **Паттерн** и **White Space**.

> **Психо-подсказка (Social Proof):** Если все конкуренты используют один стиль — НЕ копировать. White space = возможность дифференциации. См. references/social-psychology.md § In-group Signaling.

**Если WebFetch не вернул полный HTML:** Записать "данные неполные, нужна ручная проверка" — НЕ додумывать.

### 1.3 Анализ референсов (admired_brands)

**Инструмент:** `WebFetch(admired_brands[].url)` для каждого

Для каждого записать:
1. Что нравится клиенту (стиль? тон? цвета? подход?)
2. Конкретные приёмы для заимствования
3. Что НЕ подходит нашему клиенту (с обоснованием)

### 1.4 Анализ эталонных логотипов (liked_logos)

**Инструмент:** Знание + WebSearch если нужны детали

Заполнить таблицу из шаблона: тип, пропорции, вес линий, spacing, симметрия, serif/sans, регистр.

**Вывод:** что из этого применимо к нашему клиенту, что нет, почему.

### 1.5 Positioning Map

Выбрать 2 оси (самые важные для дифференциации).
Нанести конкурентов. Определить целевую позицию.
Обосновать: почему эта позиция свободна и подходит клиенту.

### GATE 1

Проверить `output/<client>/brief-analysis.md`:
- [ ] Таблица конкурентов: ≥ 2 строки заполнены данными
- [ ] White Space: конкретное описание (не "есть возможности")
- [ ] Каждый URL из брифа открыт через WebFetch
- [ ] liked_logos проанализированы (если указаны)
- [ ] Positioning map с обоснованием
- [ ] Дифференциатор — одно предложение

**Если хоть один пункт не выполнен — НЕ переходить к Фазе 2.**

## ФАЗА 2: БРЕНД-СТРАТЕГИЯ

**Артефакт:** `output/<client>/brand-strategy.md`
**Шаблон:** `templates/strategy/brand-strategy-template.md`

### 2.1 Архетип бренда

**Инструмент:** `Read(references/archetypes.md)` → матрица шкалы→архетип

1. Отфильтровать по шкалам брифа
2. Сопоставить с brand_words
3. Проверить по tone
4. Исключить архетипы конкурентов
5. Выбрать основной (70%) + влияющий (30%)

### 2.2 Цветовая палитра

**Инструмент:** `Read(references/color-psychology.md)` → 5 критериев

1. Отрасль → базовые цвета
2. Архетип → уточнение
3. Аудитория → тональность
4. Конкуренты → дифференциация (white space из Фазы 1)
5. Структура: 5 цветов (primary, secondary, accent, light, dark)

**Обязательно:** Проверить контраст Dark на Light ≥ 4.5:1.
**Обязательно:** Учесть avoid_colors из брифа.
**Обязательно:** Культурная проверка (references/color-psychology.md § Культурные нюансы).

> **Психо-подсказка:** Цвет запоминается на 80% лучше формы. Один уникальный оттенок primary > пять "красивых" цветов. См. references/social-psychology.md § Halo Effect.

### 2.3 Типографическая пара

**Инструмент:** `Read(references/font-matrix.md)` → матрица архетип→пара

1. Выбрать по архетипу
2. Проверить кириллицу (если клиент СНГ)
3. Сверить с liked_logos (пропорции, контраст штрихов)
4. Выбрать вес: Light = элегантность, Bold = уверенность

> **Психо-подсказка:** Типографика = 60-70% восприятия бренда (Halo Effect). Если бюджет Старт — это главная инвестиция.

### 2.4 Tone of Voice

Из архетипа + tone брифа → конкретные примеры:
- 3 фразы "мы говорим так"
- 3 фразы "мы НЕ говорим так"
- Стиль обращения (вы/ты/обезличенно)

### 2.5 Стиль изображений и декора

По архетипу + шкалам:
- Фотостиль (настроение, свет, тональность)
- Декор (рамки, линии, паттерны)
- Углы (скруглённые / острые)
- In-group код (references/social-psychology.md § In-group Signaling)

### GATE 2

Проверить `output/<client>/brand-strategy.md`:
- [ ] Архетип выбран с обоснованием через шкалы + words + tone
- [ ] Каждый цвет имеет обоснование через 5 критериев
- [ ] Контраст проверен (конкретные числа)
- [ ] Шрифты проверены на кириллицу
- [ ] Tone of Voice с конкретными примерами фраз
- [ ] Психо-чеклист из шаблона пройден (все 9 пунктов)

**Если хоть один пункт не выполнен — НЕ переходить к Фазе 3.**

---

## ФАЗА 3: ПРЕВЬЮ КЛИЕНТУ

### 3.1 Создать превью

**Инструмент:** Write(output/<client>/palette-preview.html)

На одном экране: палитра + шрифтовая пара + логотип (если готов).
Минимально — палитра + шрифты + настроение.

### 3.2 Визуальная проверка

**Инструмент:** Playwright → скриншот

Проверить: шрифты загрузились? Цвета точные? Общее впечатление?

> **Психо-подсказка (Visceral):** Первое впечатление за 50мс. Если скриншот не вызывает "красиво" — пересмотреть.

### 3.3 Отправить клиенту

WhatsApp / email (по feedback_method из брифа).

### 3.4 Обработать фидбэк

Если правки → обновить brand-strategy.md → повторить Gate 2.
Если одобрено → переход к Фазе 4.

### GATE 3

- [ ] Клиент видел превью
- [ ] Фидбэк получен и обработан (или одобрено без правок)

## ФАЗА 4: ИСПОЛНЕНИЕ

> Существующий процесс. Подробности: CLAUDE.md + /brandbook, /businesscard, /letterhead

### 4.1 CSS дизайн-система

Из brand-strategy.md → CSS-переменные:
```css
:root {
  --color-primary: /* из стратегии */;
  --color-secondary: /* из стратегии */;
  --color-accent: /* из стратегии */;
  --color-light: /* из стратегии */;
  --color-dark: /* из стратегии */;
  --font-heading: /* из стратегии */;
  --font-body: /* из стратегии */;
  --scale: /* 1.333 Perfect Fourth (luxury/classic) или 1.25 Major Third (modern) */;
}
```

### 4.2 Логотип

SVG outlined → assets/logos/<client>/ (logo.svg, logo-light.svg, icon.svg)
Проверить: читаем в favicon 16px? аватарка 64px?

### 4.3 Deliverables по пакету

Из CLAUDE.md → секции по пакету (Старт 8-12, Бизнес 17, Премиум 20+).
Каждый файл — один HTML с встроенным CSS/JS.

### 4.4 Аудит дизайна vs стратегия (ОБЯЗАТЕЛЬНО)

**Инструмент:** Read(brand-strategy.md) + Read(каждый HTML) + Playwright

Для КАЖДОГО deliverable — пройти чеклист:

| Вопрос из стратегии | Где проверить | Что делать если не совпадает |
|---------------------|---------------|----------------------------|
| Архетип (Lover? Ruler? etc.) | Обложка, общее настроение | Изменить фон, рамки, тон |
| luxury шкала (≤3 = тёплый) | Обложка, фоны секций | Тёмный фон → светлый, двойная рамка → одинарная |
| Tone of Voice | Тексты, формулировки | Переписать, добавить секцию ToV |
| In-group код | Декор, углы, spacing | Привести к коду сегмента |
| Палитра 5 цветов | CSS-переменные | Сверить HEX с brand-strategy.md |
| Шрифтовая пара + вес | CSS font-family, font-weight | Сверить с brand-strategy.md |

**Правило:** Документ стратегии БЕЗ применения к дизайну = бесполезная бумага. Каждое решение из brand-strategy.md ДОЛЖНО быть видно в HTML.

**Антипаттерн:** Заполнить стратегию → посмотреть что дизайн "и так нормальный" → не менять ничего → сдать. Это НЕ применение алгоритма.

### 4.5 Quality Check

**Инструмент:** Playwright

1. Скриншот каждой секции
2. Шрифты загрузились? Логотип отображается? Цвета по палитре?
3. @media print? Page-break?
4. Если ошибки → исправить → повторить

> **Психо-подсказка (Mere Exposure):** Проверить consistency — CSS-переменные одинаковы во ВСЕХ файлах? Один --color-primary везде?

### GATE 4

- [ ] **Аудит vs стратегия пройден** (таблица 4.4 заполнена для каждого файла)
- [ ] Обложка соответствует архетипу и шкале luxury (НЕ по умолчанию "тёмный + двойная рамка")
- [ ] Tone of Voice присутствует в брендбуке (примеры фраз, не абстракция)
- [ ] Все deliverables проверены через Playwright
- [ ] Шрифты, логотип, цвета — корректны
- [ ] @media print работает
- [ ] Логотип читаем в минимальном размере (favicon, аватарка)

**Если аудит vs стратегия НЕ пройден — НЕ переходить к доставке.**

## ФАЗА 5: ДОСТАВКА

1. Обновить `output/<client>/brand.json`
2. `node scripts/deliver-v2.js <client-name>`
3. Проверить ZIP: PDF в корне, PNG не пустые, шрифты скачались
4. Отправить клиенту
