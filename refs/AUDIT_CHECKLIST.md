# Чек-лист аудита deliverables

> Каждый deliverable проверяется по этому чек-листу ПЕРЕД сдачей.
> Проверка — grep/Read/Playwright, НЕ по памяти и НЕ на глаз.

---

## A. Данные клиента (сверка с brief-response.json)

Источник правды: `output/<client>/brief-response.json`

- [ ] A1. Название компании — точное совпадение (grep по всем HTML)
- [ ] A2. Имя контактного лица — если указано
- [ ] A3. Телефон — формат и цифры
- [ ] A4. Email — точное совпадение
- [ ] A5. Адрес — полный, как в брифе
- [ ] A6. Сайт, должность — если указаны

## B. Сверка с brand-strategy.md

Источник правды: `output/<client>/brand-strategy.md`

- [ ] B1. Архетип → обложка соответствует (Ruler=тёмный, Lover=светлый, etc.)
- [ ] B2. Палитра в HTML = палитра в стратегии (grep HEX-коды)
- [ ] B3. Шрифтовая пара = стратегия (grep font-family)
- [ ] B4. Tone of Voice присутствует в брендбуке (если пакет Старт+ )
- [ ] B5. luxury-шкала из брифа → уровень декора соответствует (luxury=2 ≠ двойная рамка везде)

## C. Консистентность между файлами

- [ ] C1. Данные в brandbook.html = business-cards.html = letterhead (grep)
- [ ] C2. Палитра в brand.json = HTML-файлы = PDF
- [ ] C3. Шрифты одинаковые во всех файлах
- [ ] C4. Логотип — из assets/logos/<client>/, inline SVG, не текстом

## D. Визуальное качество (Playwright)

- [ ] D1. Каждый HTML открыт через Playwright — скриншот сделан
- [ ] D2. Логотип отображается (не placeholder, не битая ссылка)
- [ ] D3. Шрифты загрузились (Google Fonts, не fallback serif/sans)
- [ ] D4. Цвета соответствуют палитре (визуально)
- [ ] D5. @media print работает — page-break на каждом section
- [ ] D6. Двуязычность (RU+EN) если клиент из ОАЭ/СНГ

## E. Функциональность по типу файла

### Брендбук / визитки (только просмотр):
- [ ] E1. HTML открывается, интерактив работает (copy HEX, навигация)
- [ ] E2. PDF из print/ — текст не растрирован, логотип чёткий

### Бланк для контрактов (клиент вписывает текст):
- [ ] E3. Формат = fillable PDF (reportlab), НЕ обычный PDF
- [ ] E4. Текстовое поле кликабельно, можно печатать
- [ ] E5. Шапка/футер не сдвигаются при вводе текста
- [ ] E6. Грабли reportlab проверены (см. memory: reference_fillable_pdf)

## F. Доставка (deliver-v2.js)

- [ ] F1. brand.json формат: `palette: {"Name": {hex, rgb, usage}}` — не плоский
- [ ] F2. ZIP < 25 МБ (лимит мессенджеров)
- [ ] F3. PDF в корне ZIP, HTML в Interactive/
- [ ] F4. README двуязычный
- [ ] F5. Имена файлов понятные, без спецсимволов
- [ ] F6. Превью ключевого PDF в Telegram/WhatsApp — не ломается

## G. Scope check ("Что за рамкой?")

- [ ] G1. Какие файлы кроме целевых были изменены? (`git diff --name-only` или grep по изменённым строкам)
- [ ] G2. Нет побочных эффектов: replace_all / переименования не сломали другие файлы (grep по old_string)
- [ ] G3. Удалённые/переименованные файлы — никто на них не ссылается (grep по имени файла)

---

## Как применять

1. Перед сдачей — пройти ВСЕ применимые пункты (пропускать только неприменимые к пакету)
2. Каждый пункт = конкретное действие (grep, Read, Playwright), не "посмотрел глазами"
3. Если пункт не пройден — исправить, пройти повторно
4. Максимум 2 круга исправлений. Если на третьем — показать Юрию
5. Результат аудита = строка в протоколе "Проверено": `✓ AUDIT A1-F6 | Риск: ...`
